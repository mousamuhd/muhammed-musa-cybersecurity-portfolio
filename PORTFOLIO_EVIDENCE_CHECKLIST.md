# Portfolio Evidence Checklist

Use this checklist before making the repository public.

## General
- [ ] Replace any placeholders with verified information only.
- [ ] Remove personal, client, company-confidential and account data.
- [ ] Make sure screenshots do not show passwords, tokens, cookies or private IP details you do not want public.
- [ ] Keep the lab scope and authorization statement in every project.
- [ ] Do not invent scan findings, recovery counts or successful cracking results.

## Project 01 – Nmap
- [ ] Add original sanitized Nmap output.
- [ ] Add a screenshot showing the command and summary.
- [ ] Explain what the open ports/services mean.
- [ ] Include defensive recommendations.

## Project 02 – Nessus
- [ ] Add scan date, authorized target identifier and scan policy.
- [ ] Add actual severity counts from the report.
- [ ] Include one or two validated findings and their evidence.
- [ ] Explain remediation and whether a rescan was performed.

## Project 03 – Burp Suite / OWASP ZAP / DVWA
- [ ] Add screenshots from the local training environment.
- [ ] Show request/response observations with secrets redacted.
- [ ] Describe the DVWA modules actually practised.
- [ ] Include defensive mitigations.

## Project 04 – Autopsy / PhotoRec
- [ ] Identify the sample evidence source.
- [ ] Record acquisition details and hashes if calculated.
- [ ] Add sanitized Autopsy and PhotoRec screenshots.
- [ ] Report actual recovered file counts/types only if verified.

## Project 05 – Hashcat
- [ ] Add the actual final Hashcat summary.
- [ ] Record number of hashes tested and recovered.
- [ ] Keep the sample hashes clearly identified as test data.
- [ ] Do not include any real account hashes or passwords.
